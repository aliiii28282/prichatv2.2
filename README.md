# ربات چت ناشناس تلگرام — نسخه Python مخصوص Railway

ربات چت ناشناس حرفه‌ای، کاملاً فارسی و راست‌چین، با اجرای Long Polling دائمی روی Railway،
ذخیره‌سازی JSON ساختاریافته روی Railway Volume (بدون هیچ دیتابیس SQL)، تاریخ و ساعت دقیق ایران
(Asia/Tehran + شمسی)، پنل مالک کامل، بکاپ/بازیابی قابل اعتماد و دکمه‌های رنگی واقعی تلگرام
(استایل رسمی Bot API 9.4: `primary` / `success` / `danger`).

**نسخه ۲.۰.۰ — جدیدها:**
- حذف دکمه «پشتیبانی» از منو؛ پشتیبانی فقط با کلمه «پشتیبانی» یا دستور `/support`
- حذف کامل ایموجی‌های رنگی از متن دکمه‌ها؛ رنگ فقط با استایل رسمی تلگرام (متن و رنگ مستقل)
- «تنظیمات پیشرفته» در پنل مالک: مدیریت دکمه‌ها (تغییر نام/رنگ/چیدمان ردیف‌ها/فعال-غیرفعال/بازنشانی) با پیش‌نویس، پیش‌نمایش واقعی کیبورد و ذخیره پس از تأیید
- مدیریت دستورات: تغییر عنوان/توضیح/نمونه/ترتیب فقط برای راهنما — عملکرد دستورها هرگز تغییر نمی‌کند
- راهنمای هوشمند جست‌وجوپذیر (`/guide` یا دکمه «راهنما و دستورات») با ۷ دسته دستور و سطح دسترسی
- کد اختصاصی مالک با امکان لغو (Revoke) و تولید کد جدید در پنل
- ارسال پیام همیشه HTML با فالبک حذف تگ — هیچ تگ خامی هرگز نمایش داده نمی‌شود
- اصلاح کامل ثبت‌نام (کیبورد استان و منبع واحد وضعیت `registered`) و `/info` مالک بدون نیاز به ثبت‌نام
- بکاپ خودکار «pre_update» از کل فایل‌های /data هنگام استقرار نسخه جدید — بدون Reset هیچ داده‌ای

## فایل‌های پروژه

| فایل | نقش |
| --- | --- |
| `bot.py` | کل ربات در یک فایل اصلی (بدون ماژول اضافه) |
| `requirements.txt` | وابستگی‌ها: `python-telegram-bot>=22.7` (پشتیبانی رسمی استایل دکمه‌ها) و `jdatetime` |
| `railway.json` | پیکربندی Railway؛ دستور اجرا: `python bot.py` |
| `tests_bot.py` | تست‌های واقعی Unit و Integration (بدون نیاز به توکن) |

> دلیل فایل‌های کمکی: `requirements.txt` و `railway.json` برای استقرار Railway الزامی‌اند و
> `tests_bot.py` طبق الزامات بخش «تست و تحویل» لازم است. هیچ ماژول دیگری به ربات اضافه نشده است.

## متغیرهای محیطی

| متغیر | الزامی | توضیح |
| --- | --- | --- |
| `BOT_TOKEN` | ✅ | توکن ربات از @BotFather |
| `OWNER_ID` | ✅ | شناسه عددی تلگرام مالک (پنل مدیریت فقط برای همین شناسه فعال می‌شود) |
| `DATA_DIR` | ⬜ | مسیر ذخیره‌سازی پایدار — پیش‌فرض `/data` |

> توضیح: طبق اصلاحات نهایی، ذخیره‌سازی SQLite حذف شد؛ بنابراین متغیر `DB_PATH` دیگر کاربرد ندارد
> و به‌جای آن `DATA_DIR` معرفی شده است. هیچ توکن یا Secret در سورس کد قرار ندارد.

## استقرار روی Railway (گام‌به‌گام)

1. پروژه را در یک مخزن Git قرار دهید و در Railway از **New Project → Deploy from GitHub repo** استفاده کنید.
2. در تب **Variables** سه متغیر بالا را تنظیم کنید (`DATA_DIR` را روی `/data` بگذارید).
3. **ساخت Volume**: از تب سرویس، **Volumes → New Volume** و مسیر Mount را دقیقاً `/data` بگذارید.
   ⚠️ بدون Volume، ربات برای جلوگیری از کار ناامن، با خطای واضح متوقف می‌شود (اطلاعات فقط در RAM نمی‌ماند).
4. فایل `railway.json` دستور اجرا را `python bot.py` تعیین می‌کند؛ Railway با NixPackS
   `requirements.txt` را تشخیص داده و نصب می‌کند (`pip install -r requirements.txt`).
5. **تعداد Replica باید ۱ باشد** (قفل فایل `bot.lock` هم اجرای هم‌زمان دو نمونه را متوقف می‌کند).
6. ربات Updateها را با Long Polling می‌گیرد؛ نیازی به Webhook یا دامنه نیست.
   قطعی‌های موقت شبکه با تلاش مجدد خودکار PTB و `restartPolicy: ON_FAILURE` مدیریت می‌شود.
7. توقف ایمن هنگام Redeploy با SIGTERM و `post_stop` انجام می‌شود.

## اجرای محلی (تست)

```bash
pip install -r requirements.txt
export BOT_TOKEN="..."      # توکن واقعی
export OWNER_ID="123456789" # شناسه عددی شما
export DATA_DIR="./data"    # در تست محلی مسیر نسبی هم مجاز است
python bot.py
```

## ذخیره‌سازی

- همه داده‌ها در فایل‌های JSON مجزا و ساختاریافته زیر `DATA_DIR` نگهداری می‌شوند:
  `users.json`, `settings.json`, `conversations.json`, `blocks.json`, `reports.json`,
  `warnings.json`, `bans.json`, `tickets.json`, `support_messages.json`, `friend_requests.json`,
  `relationships.json`, `mandatory_channels.json`, `profanity_words.json`, `scheduled_tasks.json`,
  `audit.json`, `moderation_logs.json`, `backup_history.json`, `processed_updates.json`, `button_styles.json`
  و پیام‌های هر مکالمه در `messages/conv-<id>.json`.
- هر نوشتن: فایل موقت → اعتبارسنجی JSON → **Atomic Replace** (`os.replace`) + `fsync` → نسخه `.bak`.
  اگر فایل اصلی خراب شود، به‌طور خودکار از `.bak` بازیابی می‌شود.
- قفل سراسری تراکنش + قفل هر فایل برای کنترل درخواست‌های هم‌زمان.
- هیچ اطلاعات مهمی فقط در RAM نیست؛ تنها کش در حافظه، رونوشت داده‌های روی دیسک است.

## نگهداری پیام‌ها (۷۲ ساعت)

- پیام‌های کاربران عادی پس از **۷۲ ساعت** خودکار و دائمی حذف می‌شوند (حلقه نگهبان هر ~۱ دقیقه).
- استثناها: پیام‌های **مدیر اصلی** دائمی‌اند تا خود مدیر حذف کند؛ مکالمه دارای **گزارش باز** تا رسیدگی نگه داشته می‌شود.
- پیام حذف‌شده در سوابق مجاز رسیدگی با برچسب «حذف شده» نمایش داده می‌شود.
- گزینه «del all / حذف همه» فقط در پنل مالک → «چت‌های مدیر» دیده می‌شود و پیام‌های مدیر را از سرور
  **و نمای طرف مقابل** حذف می‌کند؛ پیام‌های کاربران مقابل دست‌نخورده می‌ماند.

## بکاپ و بازیابی

- پنل مالک → «💾 مدیریت بکاپ»: ایجاد دستی، دریافت فایل از تلگرام، فهرست بکاپ‌ها، بررسی سلامت
  (SHA-256 + اعتبارسنجی ساختار) و آپلود/بازیابی.
- بکاپ خودکار با فاصله قابل تنظیم (پیش‌فرض ۲۴ ساعت) در `DATA_DIR/backups`؛ نسخه‌های «خودکار» قدیمی‌تر از
  سقف نگهداری (پیش‌فرض ۳۰) حذف می‌شوند؛ **بکاپ‌های دستی هرگز خودکار حذف نمی‌شوند**.
- بازیابی: حالت نگهداری → بکاپ از وضعیت فعلی → اعتبارسنجی نسخه آزمایشی → جایگزینی اتمیک فایل به فایل
  → بازسازی کش‌ها → بررسی واقعی تعداد رکوردها → گزارش نتیجه. در هر شکست، دیتابیس قبلی حفظ می‌شود.

## دکمه‌های رنگی

از فیلد رسمی `style` در Bot API 9.4 استفاده شده است (`python-telegram-bot>=22.7`).
مقادیر مجاز فقط `primary`، `success`، `danger` و بدون استایل است؛ رنگ دلخواه HEX پشتیبانی نمی‌شود و
نمایش نهایی به نسخه کلاینت تلگرام کاربر بستگی دارد. مالک می‌تواند استایل هر دکمه را در پنل
«🎨 ظاهر و رنگ دکمه‌ها» مستقلاً تغییر دهد، پیش‌نمایش ببیند و بدون Restart ذخیره کند.

## امنیت

- کنترل دسترسی مالک با `OWNER_ID`؛ تمام ورودی‌ها اعتبارسنجی می‌شوند؛ ذخیره‌سازی JSON با پارامترهای امن است.
- توکن فقط از متغیر محیطی خوانده می‌شود و در لاگ‌ها هرگز نوشته نمی‌شود.
- گزارش کاربر: واژه «گزارش» یا `/report` در حین چت → بستن خودکار مکالمه، ثبت گزارش با وضعیت
  «جدید / در حال بررسی / بررسی‌شده»، عدم افشای هویت گزارش‌دهنده، جلوگیری از گزارش تکراری برای یک چت.
  هیچ دکمه «گزارش» در رابط چت وجود ندارد.
- دستور محرمانه «روشن» فقط برای مالک در حین مکالمه پیام سیستمی «کاربر مورد نظر ادمین است. 💯» می‌فرستد
  و در گزارش امنیتی ثبت می‌شود؛ کاربران عادی هیچ بازخورد مدیریتی نمی‌گیرند.
- مدیر اصلی: بدون اخطار/بن/سکوت، بدون محدودیت ۷۲ ساعته، بدون فیلتر فحاشی؛ اما مشمول محدودیت فرمت‌های ممنوع.
- دستورات مدیریتی متنی (`سکوت{دقیقه}`، `بن{دقیقه}`، `اخطار`، `حذف سکوت`، `حذف بن`، `گزارش`) فقط در
  زمینه ارسال پیام به کاربر مشخص در پنل مالک کار می‌کنند و هرگز به‌عنوان پیام عادی ارسال نمی‌شوند.

## قوانین توسعه (برای تغییرات آینده)

1. قبل از هر تغییر مهم، از پنل «مدیریت بکاپ» بکاپ بگیرید (یا از فایل‌های `DATA_DIR` کپی بگیرید).
2. هرگز دیتابیس را Reset نکنید و هیچ داده‌ای بدون دستور صریح مالک حذف نشود.
3. نسخه ساختار داده `SCHEMA_VERSION` در `bot.py` است؛ در تغییر ساختار، عدد را افزایش دهید و
   اعتبارسنجی بکاپ را همگام کنید.
4. بعد از هر تغییر، `python -m py_compile bot.py` و `python tests_bot.py` را اجرا کنید.

## محدودیت‌های شناخته‌شده (شفاف)

- در محیط توسعه این پروژه، امکان اجرای آزمون واقعی با توکن تلگرام و سرور Railway وجود نداشت؛
  تست‌های انجام‌شده Unit/Integration واقعی روی موتورها، ذخیره‌سازی، بکاپ/بازیابی و منطق مکالمه هستند
  و «آزمون روی کلاینت واقعی تلگرام» باید پس از استقرار توسط مالک انجام شود.
- عملیات JSON روی دیسک برای مقیاس هزاران کاربر هم‌زمان بهینه نیست؛ برای ربات‌های چت ناشناس با حجم
  متوسط (چند هزار کاربر) مناسب است.
- پرچم ضدتکرار Update هر ۱۵ ثانیه روی دیسک ثبت می‌شود؛ در فاصله کوتاه بین خرابی و آخرین ثبت،
  حداکثر چند Update ممکن است یک‌بار دیگر پردازش شود (اثر عملی: تکرار یک پیام).
- فایل بکاپ حاوی داده خصوصی کاربران است؛ فقط از طریق پنل مالک و تلگرام مالک منتقل می‌شود.
